## Source access

The complete exact preferred-form application source `.tar.xz`/`.dsc` sits next
to the binary, with Debian build/test/resource/VAPI controls, translations and
all original notices. Dark Reader preferred source and libytnef source are
provided as companions. No credential, real profile, signing key or build log
is part of that archive. The source commit is recorded separately from the
reporting branch tip and binary/source hashes.

The native dependency index maps 134 resolved Ubuntu runtime binary packages
to 104 exact source packages and 351 HTTPS source-file locations, with strong
checksums. All locations were reachable at preflight. The standalone source
fetch helper verifies each file's exact size and SHA-512/SHA-256 checksum; its
real libytnef download/verification path was exercised. The full optional
native source set is about 632 MB. No runtime image is bundled and no blanket
claim that every `/usr` library is exempt is made. See
[corresponding-source controls](CORRESPONDING-SOURCE.md).

## Acceptance and support boundaries

The existing .7 baseline passed 328 engine + 69 focused + 10 flag cases,
three metadata targets and eight real GTK/HTTPS package-picture scenarios.
The .8 release manifest records the final repeated package checks; baseline
results are not substituted for those final results.

The rootless build uses official Ubuntu distribution files with normal clean
packaging. `-d`/`nocheck` bypass incomplete rootless bootstrap status and nested
namespace restrictions; those flags are not claimed as passing tests. Tests
run independently in fresh outer isolation with synthetic HOME, private buses/
display and loopback-only network. The software display has no GPU; nested
Glycin isolation and EDS source-registry activation are unavailable in that
minimal fixture. Production TLS verification/isolation is not disabled.

No real-account/send/move/delete workflow, full accessibility, system-wide
TerraLinux installation or configured OmniLinux upgrade is certified. Native
package/app-ID/profile compatibility is preserved and an unpack/retention check
uses synthetic profiles. Recipients should treat this as a preview with those
limits, not an already accepted replacement for every personal-mail workflow.
This engineering/source-notice review is not a blanket legal guarantee or
independent investigation of every upstream contributor's underlying rights.
